# Android reliability review

Reviewed 18 October 2026 following reports of movie subtitle import crashes and large media import failures on a Vivo V2055 running Android 13. The report did not include a failing file, app version or stack trace. The defects below are verified in source and regression tests; attribution to that particular device remains to be checked with the customer's files.

The changes address import, precise long-timeline editing, bounded export memory, custom LUT data, project durability and playback timing. The follow-up also implements the remaining source-level findings listed below. Production quality comparable to a mature editor still requires physical-device memory, decoder, interaction and image/audio qualification; feature count or JVM tests alone do not establish that quality.

## Changes implemented

All source paths in this section are relative to `Openreel Video Android/app/src/main/java/com/pythonxi/openreelvideo/`.

| Area | Verified defect and change | Regression coverage |
| --- | --- | --- |
| Subtitle import | `state/AppState.kt` previously read, parsed and mirrored the entire SRT on Main. Reading now uses IO, mirror construction uses Default, and the operation reports progress, supports cancellation, preserves concurrent edits and reports errors. | Subtitle parser | `core/subtitles/SRTParser.kt` previously made whole-file string/split copies. Parsing now holds a bounded input buffer and current cue. Limits: 8 Mi decoded characters, 20,000 cues, 64 Ki characters per cue/line. | Oversized line rejection, invalid times, compact arrows and literal dialogue arrows. |

A fixed-size moving time window now maps Double timeline times into small local drawing coordinates. Fine zoom no longer shrinks with movie duration. Every lane, ruler, thumbnail and waveform is clipped/queried to the viewport; scrubbing snaps to actual project frames while preserving fractional pan accumulation. | Movie duration at high zoom/density; 12,000-item interval queries; overlap/layer-order comparisons with a reference scan. |
| Caption preview and panels | Preview scanned all cues per frame; Text and Transcript panels eagerly composed whole projects. An immutable interval index selects active text/subtitles, panels use lazy rows, and transcript token/index preparation runs off Main. | Interval-index tests and application compilation. UI interaction qualification remains below. |
| Media copy | `core/media/MediaImportService.kt` now uses a 64 KiB copy buffer with Long byte counts, preflights known sizes, periodically checks disk space for unknown sizes, reserves 16 MiB for saves, rejects truncated/empty/unreadable media, and cleans failed or cancelled copies. | Thumbnail memory | `core/filters/FilterThumbnailRenderer.kt`, `core/render/VideoFrameSampler.kt` and timeline image requests decode at the required size, instead of allocating the original image/video frame and shrinking afterward. Temporary decoded frames are recycled. | Sampled image decode; requested video dimensions; temporary bitmap recycling. |
| Plain caption export | `core/render/StaticTextOverlay.kt` and `core/export/ProjectExportService.kt` replace one full-frame bitmap/GL overlay per plain caption with one on-demand reusable frame for the project decoration/raster path. | Audio normalization | `core/audio/LoudnessNormalizer.kt` and the export decoder now process PCM chunks. Buffering freezes the timeline and aligns/pauses the audio lanes. Audio takes clock authority after video ends, and monotonic time covers gaps and decoration-only tails. | Preview surface lifetime | `ui/editor/PreviewSurface.kt` binds video output for the view's lifetime. Effect/media refreshes retain the existing surface wrapper; repeated binding is idempotent. Closing a covering preview restores the prior view once, and callbacks after controller release cannot rebind it. | Three output-binding regressions cover refreshes, covering-view disposal and released controllers. |
| Export dimensions and cadence | `core/export/ProjectExportService.kt` normalizes native inputs to canvas pixels, composites raster decorations at canvas size and applies a final `Presentation` at the selected export resolution. A bounded transparent local still supplies requested SDR timestamps, with existing compositor placements shifted to their new input indexes. Native PQ/HLG `KEEP_HDR` exports retain their video timing input instead of introducing an SDR bitmap clock. | Eight resolution/cadence regressions; real 480×270, 30 fps speed exports and the four-corner spatial-marker export passed on API 37.2. HDR hardware qualification remains pending. |
| HDR export policy | The HDR toggle now follows its displayed meaning: enabled preserves compatible HDR sources; disabled requests SDR tone mapping. Existing saved `hdr` booleans and the missing-field default remain unchanged. For pure HDR preservation, the encoded transfer is inspected before MediaStore publication; a silent Media3 SDR fallback is deleted and reported with a recoverable error, rather than retried as a successful SDR export. SDR-only effects still explicitly require tone mapping. | Five policy/output-verification and four narrow graphics-error unit tests passed. On each emulator, the capability probe passed and four HDR-source export cases were correctly classified unsupported, not HDR passes. |
| Local project saves | `core/storage/ProjectStore.kt` streams JSON into a synced temporary file and atomically replaces the document. Failed writes preserve the last saved document. Autosave records success after IO, queues snapshots, and editor close waits for the latest save. A save failure keeps the editor open; leaving releases recorder resources and history. Unhandled editor task failures reach an error boundary. | Atomic document success/failure/replacement cases. Lifecycle behavior still needs physical-device qualification. |
| Project restore | `core/storage/ProjectArchive.kt` streams JSON/media through staging, gives metadata its own 32 MiB bound, rejects duplicate media aliases/documents, bounds ignored entries and handles cancellation. Media is restored before publishing; failed restores roll back their fresh project. | Archive round trip; invalid/duplicate entries; bounded document copy; cancellation/rollback; failed-save cleanup. |
| Filter fidelity | `core/filters/FilterLutCache.kt` restores a selected LUT from verified local storage after a memory trim. Missing configured filters fail visibly instead of silently disappearing from exports. | Cache eviction/reload and missing-filter failure. |

## Follow-up fixes

The following source-level findings are implemented. Their device qualification remains part of the release checklist.

| Original priority | Area and resulting behavior | Regression coverage |
| --- | --- | --- |
| P1 | Reverse PCM is decoded in an audio-only preparation step before the A/V Transformer starts, then streamed from a local lossless WAV/RF64 file. Long offsets, a 32 KiB scratch block and frame-aligned reverse reads keep RAM independent of duration. Draining, reset, errors and managed cancellation close/delete the spool. Startup reclaims stale inactive spools without touching active files or links. | Mono/stereo reversal, split input frames, incomplete frame rejection, output exhaustion, cleanup failures and stale/live artifact handling. |
| P1 | Animated text, legacy subtitles, reverse video and fallback video render only the current encoder timestamp. One project raster output replaces lists of pre-rendered frames and per-caption GL samplers. Sources and spatial-effect scratch are released sequentially. Sequential eligible video clips reuse a native pipeline per lane; pipeline count follows concurrent layers instead of clip count. Unsupported output sizes fail before bitmap allocation; an aggregate peak interval budget includes concurrent transition renderers and their retained outputs. | 10,000 animated cue descriptors without preparation pixels; exact timestamps; bitmap reuse/recycling; cancellation/closed state; half-open cuts; memory arithmetic/overflow. |
| P1 | Reverse/fallback video uses bounded local frame decoding at actual output timestamps, with ordered color/effect passes. Per-lane transitions hold participant endpoints around the cut and preserve transparent picture-in-picture regions. The local reader uses actual presentation timestamps and their held display intervals, with a bounded metadata scan/cache instead of a nominal frame-rate offset; samples at the exclusive outpoint stay excluded. Clip fades, rotation, flipping and item timestamps now agree across Canvas/Media3 boundaries. Non-Normal decoration blends use the complete current local raster scene, avoiding frozen backgrounds and doubled alpha. | Native pixel tests for order, opacity, small overlay fades, isolated crossfades/dips, mixed normal/reverse clips, rotation, CPU effects and transparent spatial filtering. Eleven boundary regressions passed for fractional VFR holds, later stream starts, exclusive ends, reordered/negative leading PTS, EOF, scan bounds and cancellation. The actual complex PIP/caption/chart/audio export passed on API 37.2. |
| P1 | Tracking, highlight analysis, GIF extraction, still capture and graphic assets request bounded source decoding and retain pixels only while their asynchronous consumer needs them. Image fallback honors EXIF orientation. | Requested decode sizes, sampled graphics, source ownership/recycling, asynchronous cancellation and EXIF rotation/mirroring. |
| P1 | Custom 3D `.cube` files are preserved verbatim beside footage, integrity checked and carried through derivation/archives. Preview/export use all float samples with trilinear interpolation, domain limits and intensity. Shared custom parsed-table memory is limited to two LUTs; bundled filters have a separate shared two-table/8 MiB LRU and load their shader data lazily. | Known color charts, off-center interpolation, domain/intensity, malformed/oversized data, persisted reload, integrity failure, archive/copy portability and local image pixels. Shader syntax also checked with `glslangValidator`. |
| P1 | Derived short projects stage all referenced footage, graphics and LUTs, save their document, then publish atomically. Failure rolls back without replacing a good project. Media resolution honors authoritative filenames and checks local path boundaries. Export requests are guarded during preparation as well as encoding. | Missing/low-storage/cancelled derivation, replacement rollback/recovery, disabled referenced LUTs, noncurrent derived media, custom filenames and traversal/symlink rejection. |
| P1 | Playback clock now follows decoder progress and holds all active lanes when buffering. Ended decoders relinquish clock authority without repeated seeking. | Inverse source mapping, speed slices, cuts, gaps, buffering, audio handoff and premature decoder end. Reverse and codec synchronization still require device measurement. |
| P2 | Undo coalesces continuous control changes and tracks shared immutable branches under a conservative 32 MiB retained-memory budget. Bulk transcript operations run as cancellable background transactions with one undo step and revision checks. | Coalescing boundaries, undo/redo, shared and replaced caption branches, byte-budget eviction, ripple intervals and reversed source slices. |
| P2 | Fine timeline zoom uses a moving window on movie-length projects, including audio/graphics lanes and bounded thumbnail/waveform work. | Long-duration/high-density coordinates, viewport clipping, fine ruler spacing, frame-aligned scrubbing and a screen-sized snap threshold that permits one-frame moves at high zoom. |
| P2 | Archive footage limits are disk aware and use Long/ZIP64 offsets. Metadata/ignored entries and compressed expansion remain bounded. Export validates dependencies before touching the output and preserves an existing backup if validation fails. | Round trip and rollback; virtual streams above 4 GiB without writing a multi-gigabyte fixture; compressed entry checks and pre-open backup preservation. |
| P2 | Startup age/reference cleanup reclaims abandoned import/derivation stages and media-only orphan directories while protecting active jobs, saved projects and recoverable swaps/documents. | Fresh/stale/active directories, valid projects, interrupted replacements and first-save recovery. |
| P2 | Speech synthesis uses installed offline voices only, finite initialization/synthesis timeouts, unconditional engine shutdown and partial-output cleanup. | Success, missing offline voice, engine failure, timeout and cancellation. |
| P2 | Publishing reminders restore after boot/package replacement and app resume, use the authoritative saved post and mark fired only after notification delivery succeeds. Denied/disabled notifications retain the reminder for retry. | Restore, denied delivery, duplicate/stale alarm payloads and notification identity collisions. |

Custom LUT support is 3D `.cube`, 2–65 points per axis, up to 32 MiB, applied to encoded SDR RGB code values. 1D/shaper LUTs are rejected. Older approximate custom-LUT effects lack their original samples and require re-import. Export tone-maps HDR sources to SDR when these SDR-only effects are present. Direct HDR shader use and devices without float-texture support fail with a recoverable message rather than substituting another color transform. CPU fallback is 8-bit SDR and has per-pass quantization; comparison against GPU processing and source transfer metadata remains required on hardware. Enabled effects without a supported local fallback fail explicitly.

Reverse preparation writes PCM16; decoded float samples are quantized to PCM16, and unsupported raw PCM encodings receive a recoverable conversion message. Reverse PCM trades RAM for temporary local disk usage: preparation needs space for both its PCM spool and reversed WAV, plus the existing storage reserve. Preparing it before the A/V pass avoids the EOS-only audio effect stalling the bounded video/muxer pipeline. The pinned [Media3 1.11.1 muxer implementation](https://raw.githubusercontent.com/androidx/media/1.11.1/libraries/transformer/src/main/java/androidx/media3/transformer/MuxerWrapper.java) limits inter-track write-ahead. Raster budgets cover planned bitmap/source/scratch work, not an assertion about all native decoder or GPU driver allocations. The physical-device peak-memory measurements below remain necessary, particularly for 4K and many concurrent video layers.

## Local first requirements

Imported originals and project documents remain in app-controlled local storage. These fixes add no upload or cloud-render dependency. The current Android network path is the user-initiated ML Kit caption model download; recognition then runs on the device. LUTs, reverse processing, rendering, archives and installed-voice speech synthesis stay local. This is a source inspection, with network-off qualification included in the release checks.

The emulator checklist exposed EmojiCompat's dependency-provided Startup initializer requesting a downloadable font automatically. The app manifest now removes that initializer while retaining the other AndroidX Startup entries; emoji rendering uses installed system fonts. Merged-manifest inspection confirms the removal, and the complete API 33 and API 37.2 checklists passed offline.

For the next quality milestone, prioritize durable projects, bounded memory, predictable cancellation, responsive fine editing and preview/export agreement. Optional effect/catalog expansion follows those foundations. Local diagnostic export should be opt-in and exclude raw footage and subtitle content by default.

## Release qualification

No physical Android device was connected during these runs, and the user does not have the reported Vivo V2055. Vivo reproduction and HDR-screen qualification remain unverified pending hardware access; no HDR capability is assumed for the Vivo. PQ/HLG preservation, cadence and visible luminance/color require known HDR-capable hardware before HDR release signoff. The emulator results do not replace these checks, installed caption-pack qualification, OEM provider/decoder checks or signed-release validation.

1. On the reported Vivo V2055 / Android 13, import the customer's SRT and media, then repeat with a 2-hour video, a 12,000-cue SRT, UTF-16 subtitles, a multi-gigabyte MP4 and unknown-size SAF input. Open Text and Transcript, seek near the end, undo/redo, close and reopen the project.
2. Run with airplane mode and already-installed caption packs. Import, edit, restore, preview and export without network access; verify missing packs explain the required one-time download.
3. Fill storage near capacity; cancel during copying, waveform generation and caption import; kill and restart the process during save/export. Verify that saved projects reopen and incomplete files are cleaned or recoverable.
4. Measure import duration, main-thread stalls, peak Java/native/GPU memory, scrub latency and dropped preview frames on 4–6 GB Android 13 hardware. Establish baselines before choosing performance budgets. Keep import memory independent of source byte size.
5. Compare preview and exported frames/audio for fixed/variable speed, captions, transformations, transitions, multiple audio/video tracks, mute/solo, SDR, reverse, and long gaps. Separately use known HDR-capable hardware to verify PQ/HLG preservation, tone mapping, cadence and visible luminance/color; do not assume the Vivo supports HDR. Include a multi-minute reversed stereo clip with source trimming, a selected secondary audio stream, fades/ducking and a raw WAV; verify the local prepass finishes and encoding progresses without muxer starvation. Compare identity/nonlinear/domain custom LUT charts on still, video and reverse paths. Include repeated exports after Android memory trimming.
6. Validate background export, cancellation and restart on Android 13 and current supported API levels. Build the signed release with the correct upload certificate, run Play pre-launch testing, then stage the rollout and check crash/ANR changes before expanding.

## Platform references

- [Android bitmap memory guidance](https://developer.android.com/topic/performance/graphics/load-bitmap) supports decoding small previews from source bounds.
- [Media3 BitmapOverlay implementation at the pinned 1.11.1 version](https://raw.githubusercontent.com/androidx/media/1.11.1/libraries/effect/src/main/java/androidx/media3/effect/BitmapOverlay.java) checks bitmap generation IDs, allowing the static-caption texture to update when its reused bitmap changes.
- [Media3 1.11.1 frame-processor working color space](https://raw.githubusercontent.com/androidx/media/1.11.1/libraries/effect/src/main/java/androidx/media3/effect/DefaultVideoFrameProcessor.java) preserves SDR encoded RGB code values by default and treats sRGB/SMPTE 170M transfers equivalently, matching the documented untagged-cube convention above.
- [Android nearest-frame retrieval](https://developer.android.com/reference/android/media/MediaMetadataRetriever#OPTION_CLOSEST) may return a picture on either side of the requested time. [Extractor sample timestamps](https://developer.android.com/reference/android/media/MediaExtractor#getSampleTime()) identify actual presentation microseconds for enforcing source-trim boundaries.
- [AGP 9.4 compatibility](https://developer.android.com/build/releases/agp-9-4-0-release-notes) supports API 37 and requires Gradle 9.6 or newer and JDK 17 or newer. [Kotlin's Gradle compatibility guidance](https://kotlinlang.org/docs/gradle-configure-project.html) also qualifies use of newer stable Gradle/AGP releases beyond its fully tested version table; the pinned combination has passed this project's local build and unit/lint checks.
