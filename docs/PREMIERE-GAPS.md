### `.prproj` import

**Partly closed.** File > Import timeline > Premiere project (.prproj)..., or dropping a `.prproj` on the Project panel, reads a gzip Premiere project (`packages/core/src/interchange/prproj.ts`). It reads: the object graph (ObjectID/ObjectRef, ObjectUID/ObjectURef), bins and master clips (bins are recreated for offline media), the sequences with frame rate and resolution (a picker chooses which one to import; the others are listed in the report), video and audio tracks, clip items with in/out/start/end in ticks (254016000000 per second, BigInt exact), enabled/disabled (imported transparent and muted: OpenReel has no clip enable switch), constant speed and reverse, track targeting, locks and mute, Motion position/scale/rotation, Opacity and Volume level (start value), sequence markers (range markers and chapter type), cross dissolve and dip to black/white, and nested sequences (as OpenReel nested sequences). Linked audio of a video clip is merged into that video clip, like the XMEML importer. Media is relinked to the bin by file name; the rest becomes offline placeholders for the existing relink flow. The commit is one `project/applyEditSnapshot` (one undo step, bins and nested sequences included).

Everything it cannot place goes in an import report shown before the import (dropped / approximated per clip), not silently: other effects (Lumetri and every effect besides Motion/Opacity/Volume), time-remap ramps, keyframed Motion/Opacity/Volume (start value used), anchor point, blend modes, non-uniform scale, other transitions and audio crossfades, titles/captions/graphics, adjustment layers and mattes. Master-clip markers, track mixer settings and Productions are not read.

**Not verified against Premiere.** No `.prproj` written by Adobe Premiere Pro was available. The element names and layout follow Premiere's saved-project structure as it is publicly documented and remembered (`docs/interchange.md` lists the walk), the reader looks names up tolerantly, and the tests use hand-authored gzip fixtures that follow that layout. Speed/reverse, disabled, targeting and the Motion position units (normalised 0..1 vs pixels is guessed from the value range) are the least certain parts. Real projects may use element spellings that are not read yet; those clips would show up in the report or import without that property. Tested by `prproj.test.ts` (tick math, graph, report, undo) and `e2e/interchange-prproj.spec.ts`.

- **Spectral editing (closed except the items at the end):** Audio tab > Spectral editing shows an STFT spectrogram of the clip's source (log frequency axis, colour maps, time zoom and pan, computed in a worker). Selection tools: box, frequency band (whole source), **lasso** (free-form polygon), **brush** (a painted stroke with a size), **magic wand** (click a point: the connected region of similar energy, tolerance in dB relative to the clicked cell, optional local-contrast mode; the selected cells are stored as a run-length mask on the STFT grid with the seed and settings, so it renders identically after a reload whatever the algorithm later does) and **harmonic** (click a fundamental or drag a box: the pitch is tracked through time, vibrato and glides included, and its overtones up to N harmonics / a maximum frequency with a bandwidth in cents are selected as one region; the fundamental track is stored and the bands are derived from it). Every region can be limited to the left or the right channel of a stereo source (`channel`, default both). Each selection can be attenuated by N dB, removed (interpolated fill) or **healed** (refilled with the surrounding background at its own level and texture: expected power averaged over untouched cells on each side and interpolated in power, phase continued from both sides by phase-vocoder propagation, then a fixed 6 consistency passes with a tile-averaged power gain, so it is a smooth function of its input; steady partials continue across short gaps). Lasso and brush are stored as mask regions (points in source time and Hz, brush half-size in seconds and octaves) rasterised on the STFT grid as a soft mask with a feather (0 to 8 cells); the effect carries `version: 2` only when a region needs it (lasso, brush, heal) and `version: 3` only for a wand, a harmonic region or a single-channel edit, and every rectangle-only project saved before this loads and renders unchanged (same region format, same cache key, same samples). The region list selects, shows or hides, changes mode (attenuate / remove / heal) and attenuation, sets the feather and deletes; regions are drawn on the spectrogram, a selected box moves and resizes with handles and a selected lasso's points drag. Every one of those is one undo step. Edits are a "spectralRepair" clip audio effect with source-time regions, applied before every other clip effect in both the realtime preview and the export through one shared cached repair job. Agent tools (lazy group): `list_spectral_regions`, `add_spectral_region` (rect / band / lasso / brush, with a `channel` option), `update_spectral_region`, `add_spectral_magic_wand`, `add_spectral_harmonic_region`, `remove_spectral_region`, `find_spectral_tones`, `remove_spectral_tones`, `remove_spectral_clicks`. Covered by `spectral-mask.test.ts` (lasso / brush rasterisation, feather), `spectral-heal.test.ts` (whistle through speech-like harmonics, click, bit-identity outside the mask, determinism), `spectral-detect.test.ts`, `spectral-edit.test.ts` (undo / redo, v1 compatibility, save and reload), `spectral-dsp.test.ts`, `spectral-repair-cache.test.ts`, `realtime-audio-graph.spectral.test.ts`, `audio-engine.render-integration.test.ts` (preview and export samples equal the DSP's, lasso / brush / heal included), `spectral-wand-harmonic.test.ts` (tracking error in cents on an analytic vibrato and glide, harmonic energy captured against non-harmonic energy included, removal depth of a gliding whistle with harmonics under speech-like noise against a plain band, the wand on a click train and a hum, stored-cell reload, version and channel semantics), `registry.spectral.test.ts` and `e2e/spectral-editing.spec.ts` plus `e2e/spectral-masks.spec.ts` plus `e2e/spectral-wand-harmonic.spec.ts` (a real wand click and a real harmonic click, a Left-only then Right-only edit, list edits, preview and export samples within -92 dB, and a real export decoded with ffmpeg per channel; brush and lasso painted with real pointer input, heal, region list edits, export mixdown, live playback, a real export decoded with ffmpeg). Healing is measured, not assumed (see `known-limitations.md`): the first heal (Fast Griffin-Lim) was no better than interpolated remove and amplified a 3e-8 input change by 8 to 29 dB; the current one amplifies it by at most 1.6 dB, keeps the background at the right level and texture where remove leaves a 5 to 14 dB notch, and beats remove on error against the clean signal only where steady partials continue across the gap (a cough over a chord: -2.8 and -5.1 dB against +0.7). On noise, vibrato and glides the fill is uncorrelated with what was there, which scores worse than a quiet hole on raw error. Measured on analytic signals (see `known-limitations.md`): f0 median error 1.4 cents on a +-50 cent vibrato and on a 0.8 octave per second glide (p95 6 and 8.5, worst 34 and 21 at the source edge); a harmonic region holds 97.7 % of a vibrato voice's harmonic energy and 2.6 % of the noise where one band over the same range holds 97.6 % and 7.8 %; a 5-partial whistle under speech-like noise is taken down 20.6 dB by a harmonic region (speech kept at 11.6 dB SNR) against 5.0 dB by a band over its fundamental and 34.8 dB (speech at 2.0 dB) by one band over all partials; a wand on one click of a train selects only that click (16.7 dB removal) and on a 60 Hz hum selects the whole line (26.5 dB at -60 dB attenuation). Not done: the wand leaks into a chord when the sound clicked sits on it (an independent verifier found a cough over a sustained chord at 6 dB tolerance puts 21.7 % chord energy in the selection, and local-contrast mode does not help; use a lasso or brush there), the wand's tolerance is a flood threshold (raised far enough it floods the noise floor), the harmonic tracker follows one pitch (no chords, no polyphony, it can follow a louder neighbouring voice in a dense mix and the seed must be the fundamental), a wand region's cells cannot be moved (re-click), analysis is of the mono mix so a per-channel edit of a sound that is only in one channel is selected from its half-amplitude trace, per-channel stereo heals (each channel is healed on its own), and non-stationary heal that recovers the exact phase of a masked harmonic (it continues the sound plausibly, it does not reproduce the original samples).

## 1. Verdict

OpenReel is close to Premiere on the editing core. Its tool set, sync lock, three-point edits, multicam, nesting, mixer, captions and transcript editing are broad and share one undoable action path. It is also ahead on honest docs, on-device ASR and AI/MCP surface. The release-blocking gaps are a short list of correctness and fidelity problems, not missing feature families. Three things render or play wrongly today: adjustment layers hit titles and tracks above them, speed changes shift pitch, and clip pan automation is stored but silent. Alongside those sit three Premiere-workflow gaps: Q/W is not ripple trim, timeline drags cannot overwrite or insert, and nothing gates scrub or playback performance. Everything else is parity polish or depth (format breadth, plugin hosts, RAW, HDR monitoring) that can ship after a verified release. Collaboration is excluded per the owner's priorities. Impact ratings come from the audit. I read "blocker/high" as "behaves wrongly or misleads users", and that ranking is my judgement.

## 2. Must-fix before the major release

Ranked. Effort is S/M/L/XL.

1. **Adjustment layers ignore track stacking and affectedTracks** (effects, M). They hit titles, subtitles and particles, and the position-aware resolver exists but neither renderer calls it. Wrong output in both preview and export.
   Evidence: `packages/core/src/video/video-engine.ts:1371-1380,1605-1640`, `apps/web/src/components/editor/Preview.tsx:192-232,3313-3321`, `packages/core/src/video/adjustment-layer-engine.ts:270-290`.
2. **Speed changes always shift pitch; the pitchCorrection flag is stored but never read** (audio, L). A 2x clip sounds an octave up in preview and export. The flag also implies a feature that is not there, so either implement it or hide it.
   Evidence: `packages/core/src/audio/audio-engine.ts:709`, `packages/core/src/video/speed-engine.ts:16,403`, `packages/core/src/audio/mixdown-cache.ts:78`.
3. **Clip pan automation is stored and copied but never rendered** (audio, M). The schema accepts data with no audible effect. Wire it into `clip-audio-resolution.ts`, or reject and hide it until it is wired.
   Evidence: `packages/core/src/audio/clip-audio-resolution.ts:78`, `packages/core/src/types/timeline.ts:326-329`.
4. **Q/W is not Ripple Trim to Playhead, and it ignores speed and reverse** (editing, M). It leaves the gap, bypasses the sync-lock planners, and moves inPoint by timeline delta. The speed handling is a correctness bug.
   Evidence: `packages/core/src/actions/action-executor.ts:1378`, `apps/web/src/hooks/useKeyboardShortcuts.ts`.
5. **Timeline drag has no overwrite, insert or resolution** (editing, L). `clip/move` removes and re-adds the clip with no overlap handling, so a drop onto another clip can create overlaps. Add overwrite by default, with Cmd/Ctrl for insert and Alt for copy.
   Evidence: `packages/core/src/actions/action-executor.ts:1089`, `apps/web/src/components/editor/Timeline.tsx:882-910`, `ClipComponent.tsx:640-720`.
6. **Perf has no gates for scrub latency, playback fps or import** (perf, M). The current budgets are cold start (tightened 1200 -> 1100 ms in cold-start round 3, still a loaded-machine number), a 400-clip bench and memory4k. Measured scrub p95 is about 600 ms, and 4K scrub p95 is about 550 ms on original media. Add budgets and a dropped-frame indicator. Dropped frames are counted but no UI reads them (S).
   Evidence: `apps/desktop/scripts/perf-budgets.json`, `docs/soak-report.md`, `packages/core/src/playback/playback-controller.ts`.
7. **The wall-clock GA gate was never passed on an idle machine, and loaded runs silently pass** (perf, M). Run it once on a quiet reference machine with `--require-wall`. This is what "ship verified states" requires.
   Evidence: `apps/desktop/PERF.md`, `apps/desktop/scripts/perf-budget.mjs`.
8. **4K layered playback peaks at 3.7-4.0 GB and the governor underestimates decoder cost** (perf, L). Whole-file audio decode remains. Recalibrate the 149 MB per-decoder estimate and window the audio decode.
   Evidence: `packages/core/src/device/memory-governor.ts`, `docs/soak-report.md`.
9. **LUT parser silently mis-loads LUTs** (color, M). DOMAIN_MIN/MAX is ignored, there is no 1D support, and data is stored as 8-bit. Wrong colour with no error.
   Evidence: `apps/web/src/components/editor/inspector/LUTLoader.tsx:42-92`.
10. **Export presets can be written but not saved from the UI** (export, M). `ExportPresetsManager` has a full API that nothing in the editor calls. This is a daily workflow.
    Evidence: `apps/web/src/services/export-presets.ts:844-960`, `ExportDialog.tsx:690`.

It applies wherever a program frame's source time falls between two source frames: slow motion, speed ramps, reverse, and frame-rate conform (25 fps footage in a 30 fps sequence). Frame Blending is the exact weighted blend `(1 - t) * a + t * b` of the two nearest frames. Optical Flow is a dense bidirectional pyramidal Lucas-Kanade flow on contrast-normalised luma (so a fade or a flicker is not read as motion), median-filtered per level, with a forward/backward consistency and a windowed match-error confidence; each output pixel is built from both frames at their motion-compensated positions (the flow projected to instant t by fixed-point iteration), weighted by confidence and photometric agreement, with the plain blend as the fallback where confidence is low (occlusions, unrelated content). Finished frames are cached by source, frame pair, t, mode, quality and size; the flow of a frame pair is cached separately so the three intermediates at 25% speed cost one estimation (`time-interpolation.test.ts` counts the decodes and estimations); the render cache (Sequence > Render In to Out) renders them like any other heavy segment, the status bar shows an Optical Flow clip red and the rendered stretch green (`e2e/render-cache.spec.ts`). **Planar and corner-pin tracking: done** (`packages/core/src/video/planar-track.ts`, `planar-homography.ts`, `apps/web/src/services/planar-track-apply.ts`, `corner-pin-edit.ts`). A quad drawn on the Program monitor is tracked forward, backward or over the whole clip in a worker (cancellable, with progress and a per-frame confidence). Shi-Tomasi features inside the quad are followed with pyramidal Lucas-Kanade (forward-backward checked), and a RANSAC homography is fitted from the anchor frame to each frame, then refined by matching every point's patch directly against the anchor frame, so error does not accumulate. Ground truth on synthetic perspective footage (64 frames, sensor noise up to about 14 grey levels, a moving occluder): worst corner error 0.41 px (`planar-track.accuracy.test.ts`). The track can be applied to a clip as a keyframed Corner Pin effect (full perspective), as a four-point mask that follows the surface (on any clip, including the tracked footage), or as Position, Scale and Rotation keyframes that fit the clip onto the surface. All three are one undo step, are saved with the project, re-derive when the track is re-tracked or a corner is edited, and render identically in preview and export (`e2e/planar-track.spec.ts`). The Corner Pin effect also has draggable handles on the Program monitor, keyframed when a corner is animated (`e2e/corner-pin-parity.spec.ts` checks the GPU shader against the CPU reference).

### Premiere Motion Graphics Templates (.mogrt) import

**Partly closed (Premiere-authored only).** Essential Graphics > Browse > Import template... (and the same file picker) accepts `.mogrt`. A .mogrt is a zip; `packages/core/src/graphic-templates/mogrt/` reads `definition.json` (editable controls), the Premiere graphic (`*.prgraphic` or `project.prproj`, gzip or plain XML) and the thumbnail, and builds an ordinary OpenReel graphic template (so it expands to text / shape / image clips and renders in preview, export and nests like any other template). The parser loads on demand (not in the entry chunk).

Mapped: text layers (font family and style to weight and italic, size, fill colour, left / centre / right / justify, tracking to letter spacing, leading to line height, stroke, drop shadow, underline, all caps), rectangles (fill, gradient, corner radius, stroke, shadow), ellipses, embedded png / jpeg / webp / gif images, layer position, anchor point, scale and rotation (baked into the box), opacity, group position and opacity, hidden layers, and keyframes on position, scale, rotation and opacity (with hold / linear / ease interpolation; times before the protected outro are anchored to the start, times inside it to the end). The responsive-time intro and outro durations become the template's protected intro and outro. Editable controls become Essential Graphics-style inspector controls: text (plus the font and font-size options Premiere exposes on a text control), colour (text fill, shape fill), slider (opacity, rotation, text size, shape stroke width), checkbox (layer visibility) and point (layer position). Controls are tied to layers by `ControlID` in the graphic, then by the control's own target list, then by layer name.

The **import report** (shown under the Browse tab, also for refused files) lists every dropped or approximated item: path / line / polygon layers, masks, track mattes, layer effects, non-Normal blend modes, text animators, responsive-design pins, group scale / rotation, mixed styling inside one text layer, media-replacement controls, sliders bound to properties OpenReel cannot drive (scale, position), controls with no binding, and the preview video. **After Effects-authored .mogrt** (`authorApp` "aeft" or an `.aegraphic` / `.aep` without a Premiere graphic) are detected and refused with a clear message and the list of controls found: the AE composition cannot be rendered outside Adobe's engine.

**Not verified against Premiere.** No `.mogrt` written by Adobe's tools was available, and Adobe does not publish the format. `definition.json` fields that were checked against public sources: `authorApp`, `fonteditinfo` (`capPropFontEdit`, `capPropFontSizeEdit`, `fontEditValue`, `fontSizeEditValue`, bold / italic / all-caps flags), `textEditValue`, and the zip layout (definition.json, graphic, thumbnail). Control type GUIDs are not public, so a control's kind is inferred from a type name when there is one and otherwise from its value. The graphic XML layout (element and attribute names, pixel units, anchor semantics, time in ticks, top-first layer order, the `ControlID` binding) is a reconstruction modelled on the `.prproj` object style, read tolerantly with several spellings accepted; public sources suggest Premiere-built templates actually carry a `.prproj`, which is why that is read too. A real Premiere file may use spellings or structures that are not read yet: such layers show up as skipped in the report, or the whole file is refused as having no readable graphic. Tested with hand-authored fixtures (`mogrt.test.ts`, `graphic-commands.mogrt.test.ts`) and `e2e/mogrt-import.spec.ts` (import through the UI, edit a control, the rendered frame changes and undo restores it).
